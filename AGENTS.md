# Stack

- **Framework:** Next.js 16 (App Router, Turbopack dev), React 19
- **Backend:** Convex 1.39 (schema, queries, mutations, actions, auth, HTTP router, migrations)
- **Auth:** `@convex-dev/auth` with Password provider (Scrypt hashing, JWT custom claims for role)
- **Styling:** Tailwind CSS v4 (CSS-first config in `globals.css` via `@theme inline {}` — no `tailwind.config.js`)
- **UI:** shadcn/ui ("radix-luma" style), lucide-react, `@base-ui/react`, `radix-ui`
- **Forms/validation:** zod 4, `convex-helpers/server/zod4` for `zCustomMutation`
- **Rate limiting:** `@convex-dev/rate-limiter` (token bucket, per-user + global)
- **Migrations:** `@convex-dev/migrations`
- **Linting/formatting:** Biome 2.4 (replaces ESLint + Prettier entirely)
- **Package manager:** pnpm (single workspace, pnpm-workspace.yaml allows esbuild/msw/sharp builds)
- **Testing:** Vitest + `convex-test` (in-memory Convex backend), `@edge-runtime/vm`

| Lint only        | `pnpm lint`                        |
| Typecheck        | `pnpm typecheck` (tsc --noEmit)    |
| Deploy Convex    | `pnpm convex:deploy`               |
| Convex dashboard | `pnpm convex:dashboard`            |
| Seed database    | `pnpm seed`                        |
| Seed reset       | `pnpm seed:reset` (wipe + rebuild) |

**Both `pnpm dev` and `pnpm convex:dev` must run simultaneously** for full local dev.

`pnpm seed` is **idempotent** — it no-ops (≈0 I/O) when domain data already exists, to
protect the 1 GB/month database-I/O free-tier budget. Use `pnpm seed:reset` only when a
clean rebuild is actually needed.

**Deploy checklist (backfills).** Range reads rely on `createdAt` being present and on
denormalized totals. When deploying new range-read / export code, run the needed
backfills via the migration runner (`pnpm convex run migrations:run '{"fn":"migrations:<name>"}'`) on
the target deployment alongside the code deploy: `backfillDispatchCreatedAt`,
`backfillStockAdjustmentCreatedAt`, `backfillAuditLogCreatedAt`,
`backfillDispatchTotalQuantities`, `backfillDispatchTotalValues`, `backfillProductBatchCounts`.

# Testing

- Tests live in `convex/` next to implementation files (e.g., `convex/users/mutations.test.ts`)
- Uses `convex-test` with `convexTest({ schema, modules })`
- For functions using `getAuthUserId`/`createAccount`, use a manual module map (see `convex/auth/auth.test.ts` for canonical auth test pattern)
- Auth integration tests require `JWT_PRIVATE_KEY`, `CONVEX_SITE_URL`, `SITE_URL` env vars set in `beforeAll`
- Rate limiter must be registered in tests via `registerRateLimiter(t as never)` from `@convex-dev/rate-limiter/test`
- Some Convex internals require `ctx as unknown as never` casts
- Vitest config uses `environment: "edge-runtime"`

# Convex

- `convex/_generated/` is auto-generated by `convex dev` — do not edit
- Schema in `convex/schema.ts` — 8 tables: `users`, `products`, `suppliers`, `batches`, `dispatches`, `dispatchItems`, `stockAdjustments`, `auditLogs`
- `convex/convex.config.ts` registers third-party components: `@convex-dev/migrations` and `@convex-dev/rate-limiter`
- `convex/auth.ts` — password auth with Scrypt hashing, JWT includes `role` in custom claims for middleware
- `convex/auth.config.ts` — provider domain from `CONVEX_SITE_URL` env var
- `convex/http.ts` — registers auth HTTP routes
- `convex/server.ts` — exports `zMutation` (zod-validated mutation wrapper via `convex-helpers`)
- Roles: `owner` (full access, redirected to `/dashboard`), `staff` (products + dispatch only, redirected to `/products`)
- Route protection via `proxy.ts` middleware — decodes JWT role claim, sets `x-user-role` header
- Seeding: `convex/init.ts` seeds owner (`internalAction`, only runs on deploy, requires `OWNER_EMAIL`/`OWNER_PASSWORD` env vars). `convex/seedAction.ts` + `convex/seed.ts` provide full demo data via `pnpm seed`
- `convex/migrations.ts` — data migrations for backfilling roles/statuses, dispatch denormalized fields, supplier batchCount
- DB domain logic organized as `convex/<table>/` with files: `mutations.ts`, `queries.ts`, `validators.ts`, `*.test.ts`

# TanStack Table

All tables use `@tanstack/react-table` and follow a **Container + Pure Table** split pattern.

## Container (`*TableContainer`)

Owns all TanStack config — no UI rendering.

- `createColumnHelper<T>()`
- `useState<SortingState>` — default sort column + direction
- `useState<string | null>` for expandable row ID (manual, NOT `getExpandedRowModel`)
- `columns` in `useMemo([], [])` — stable reference, no deps
- `data` in `useMemo(() => data ?? [], [data])` — ensure array, stable ref
- `useReactTable({ data, columns, state: { sorting, columnVisibility }, meta: {...}, onSortingChange, onColumnVisibilityChange, getCoreRowModel, getSortedRowModel, enableSortingRemoval: false, isMultiSortEvent: () => false, getRowId: (row) => row._id })`
- Returns the Pure Table component, passing `table` + any expand/callback props

## Pure Table (`*Table`)

Pure render component — receives `table: ReactTable<T>`, no TanStack config imports besides `flexRender` / `ReactTable` type.

- Derives `rows = table.getRowModel().rows`, `totalColumns = table.getAllLeafColumns().length`
- Renders `<Table>` → `<TableHeader>` with sort buttons (ArrowUp/ArrowDown) via `flexRender`
- `<TableBody className="animate-fade-in">` with `<Empty>` fallback when `rows.length === 0`
- Expandable rows: `<Fragment>` with row component + detail `<TableRow colSpan={totalColumns}>`

## Column conventions

- Primary identifiers: `enableHiding: false`
- Actions column: `columnHelper.display({ id: "actions", enableSorting: false, enableHiding: false, enableGlobalFilter: false })`
- Cell renderers use `info.getValue()`, `info.row.original`, or `({ row }) =>` pattern
- Chevron rotation in expandable rows uses `meta` from table options to read `expandedId`

## Page render cascade (every table page)

```tsx
{isUserLoading || filtered === undefined ? (
  <SkeletonTable headers={[...TABLE_COLUMNS.map(c => c.label)]} actions="ellipsis" />
) : user?.role !== "owner" ? (
  <p className="text-sm text-muted-foreground">No permission...</p>
) : filtered.length > 0 ? (
  <TableContainer data={filtered} ... />
) : (
  <Empty>...</Empty>
)}
```

`filtered === undefined` signals loading (Convex query hasn't resolved). `useCurrentUser()` provides `user`, `isLoading`, `isAuthenticated`.

## Client-side filtering (via `nuqs`)

- `useQueryState("search", ...)` + `useQueryStates(parsers, { history: "replace" })`
- `filtered = useMemo(() => { if (!data) return undefined; ... }, [data, search, filters])`
- `clearFilters()` resets all query params to defaults
- `hasActiveFilters` drives empty state message ("no results match" vs "no items yet")

## SkeletonTable

- Props: `headers: string[]`, `actions: "ellipsis" | "text" | "none"`, `rowCount?: number`
- Rows fade progressively: `style={{ opacity: Math.max(1 - i * 0.2, 0.3) }}`

# Architecture

- **Convex is the sole backend** — no REST API or server-side framework beyond it
- DB domain logic in `convex/<table>/` (e.g., `convex/users/mutations.ts`)
- App pages in `app/(dashboard)/` (owner routes) and `app/(auth)/` (sign-in)
- Route protection: `proxy.ts` middleware via `@convex-dev/auth/nextjs/server` with `jwtDecode` role check
- Rate limiting: `convex/rate_limiter.ts` defines named token buckets (per-user + global safety valves)
- Audit logging: every mutation records to `auditLogs` table via `convex/auditLogs/mutations.ts`
